## 一、产品说明

### 1.1 这是什么

跟随功能让机器人**自动跟着前方的人走**，并**保持一个设定的距离**。

工作方式：摄像头拍摄画面 → 车上的人工智能模型判断"该往哪走" → 指令发给底盘 → 车动起来。距离靠深度摄像头测量，人远了就加速追，人近了就减速停。

### 1.2 能做什么

| 能力 | 说明 |
|---|---|
| 自动跟随 | 跟着前方的人前进、转向 |
| 定距保持 | 保持设定距离（可设 0.5 ~ 7.0 米） |
| 语音调距 | 说"近一点""远一点""保持 X 米"可以随时改距离 |
| 安全限速 | 前进最快 0.25 米/秒，限制加速度，指令中断自动停 |

### 1.3 不能做什么（重要）

| 限制 | 说明 |
|---|---|
| **没有避障** | 不使用雷达，不会绕开障碍物。**前方有障碍物时必须人为干预** |
| **不会选人** | 画面里是谁就跟着谁，无法指定"跟穿红衣服的" |
| **没有"无人自动停"** | 画面上没有人时，车仍可能自行移动 |
| **不能倒车** | 人比设定距离更近时，车只会停住，不会后退 |
| **不能喊停** | 没有"别跟了"这类语音指令 |

> ⚠️ **使用本功能必须有人在旁持遥控器，随时准备急停。**

## 二、使用前提

### 2.1 硬件与环境

| 项目 | 要求 |
|---|---|
| 机器人 | AgileX Ranger Mini v3，电量充足 |
| 摄像头 | Orbbec Gemini 336L 已连接 |
| 雷达 | Livox Mid-360 已连接（建图服务需要） |
| 底盘总线 | `can_ranger` 可用 |
| 遥控器 | **必须在手**，且已与底盘配对 |
| 场地 | 清空，目标距离外有足够进退空间 |

### 2.2 关键约束：跟随与导航不能同时开

跟随和导航**抢同一条底盘总线**，同时开会互相干扰。

**开跟随之前，必须先关掉导航。**

### 2.3 命令在哪里敲

**全部命令都在机器人主机的一个终端窗口里执行**（不是容器里，脚本会自动进容器）。

```bash
cd /mnt/ssd/wxf/jiaofu/skill-follow-person-rbnx    # 每条命令都从这个目录出发
sudo -v                                       # 输一次密码，屏幕不显示是正常的
```

> 为什么要 sudo：脚本要操作容器，需要管理员权限。输一次可用 5 分钟。

## 三、快速开始

```bash
# 第 1 步：进目录 + 授权
cd /mnt/ssd/wxf/jiaofu/skill-follow-person-rbnx
sudo -v

# 第 2 步：确认导航已停（看"导航栈的底盘进程"必须为 0）
bash scripts/follow.sh status

# 第 3 步：起服务（约 75 秒，成功标志 OK 条数: 16）
bash scripts/follow.sh start

# 第 4 步：健康检查（四项必须全绿）
bash scripts/follow.sh check

# 第 5 步：让被跟随的人站到车正前方
#         距离要比设定值远（例如设定 5 米，人就站 6 米）
```

打开实时监控（**建议另开一个终端常开**）：

```bash
bash scripts/follow.sh watch
```

## 四、命令详解

所有命令统一入口：`bash scripts/follow.sh <子命令>`

### 4.1 起栈 —— `start`

```bash
bash scripts/follow.sh start
```

**自动完成的检查**（不通过就拒绝启动，不会启动一半）：

| 检查项 | 不通过时的提示 |
|---|---|
| 控制端口是否空闲 | 跟随栈残留 → 先 `stop`；导航栈在跑 → 先停导航 |
| CAN 总线是否存在 | 检查 USB-CAN 适配器 |
| 历史僵尸进程 | 提示重建容器（不阻断启动） |

**成功标志**：

```
  OK 条数: 16 （应为 16）
```

**条数不对**：看启动日志

```bash
sudo docker exec robonix_follow_dev bash -lc \
  'tr "\r" "\n" < /root/deploy/logs/start_follow.log | grep FAIL'
```

### 4.2 查看状态 —— `status`

```bash
bash scripts/follow.sh status
```

显示三项：容器是否在运行、当前模式、底盘被谁控制。

**判读**：

| 显示 | 含义 |
|---|---|
| 导航栈的底盘进程 = 0 | ✅ 可以起跟随 |
| 导航栈的底盘进程 ≠ 0 | ❌ 导航还在跑，先停导航 |
| `/cmd_vel` 发布者 0 个 | 空挡模式，车不会动 |
| `/cmd_vel` 发布者 1 个 | 挂挡模式，车可以动 |
| `/cmd_vel` 发布者 >1 个 | **危险**，立刻 `stop` |

### 4.3 健康检查 —— `check`

```bash
bash scripts/follow.sh check
```

四项检查，**动车之前必须全绿**：

```
[ OK ] 推理服务已加载模型
[ OK ] 意图路由在线
[ OK ] /camera_435i/color/image_raw   ~30 Hz
[ OK ] /camera_435i/depth/image_raw   ~30 Hz
[ OK ] /camera_435i/color/camera_info ~30 Hz
[ OK ] /cmd_vel 发布者 1 个 —— live，车可以动
```

### 4.4 实时监控 —— `watch`

```bash
bash scripts/follow.sh watch          # 建议另开终端常开，Ctrl-C 退出
```

每秒刷新一张表，显示指令流经的每个环节和当前速度。**`vx` 就是车的前进速度**。

同时会显示检查点提示：`/cmd_vel` 的发布者必须恰好为 1。

### 4.5 进入容器终端 —— `shell`

```bash
bash scripts/follow.sh shell
```

用于手动排查。进入后可用的命令：

```bash
ros2 topic info /cmd_vel                        # 发布者数量
ros2 topic hz /camera_435i/depth/image_raw      # 深度帧率（定距靠它）
ros2 topic echo /cmd_vel                        # 底盘实际收到的速度
tail -f /root/deploy/rbnx-boot/logs/go2_robottrack.log   # 跟随状态日志
exit
```

### 4.6 模式切换 —— `live` / `dry-run`

| 模式 | 车会动吗 | 用途 |
|---|---|---|
| `dry-run`（空挡） | ❌ 不动 | 调试链路、初次验证 |
| `live`（挂挡） | ✅ 会动 | 实际使用 |

```bash
bash scripts/follow.sh live        # 切挂挡
bash scripts/follow.sh dry-run     # 切空挡
```

> ⚠️ **改模式必须重起才生效**：`stop` → `start`

### 4.7 关栈 —— `stop`

```bash
bash scripts/follow.sh stop
```

**推荐顺序**：

```bash
# 1. 先用遥控器把车停住
# 2. 切回空挡（下次启动默认安全）
bash scripts/follow.sh dry-run
# 3. 关服务
bash scripts/follow.sh stop
```

**关栈会自动完成的收尾**：

| 动作 | 说明 |
|---|---|
| 停掉所有组件 | 底盘、相机、模型、建图、语音 |
| 释放控制端口 | 逐个验证，没释放会报错 |
| 保留 CAN 接口 | 仅释放控制权，不拆接口 |
| **重启容器** | 收尾后重启容器，给下一轮一个干净的进程表 |

> 为什么要重启容器：关栈过程会杀掉大量进程，其中一部分会被移交给容器的 1 号进程。
> 这些残留只能靠重启清干净，否则会让"进程还在不在"的判断失准，并逐轮累积。
> 正常情况下用**重启**（不会丢容器）；只有容器的 1 号进程本身不回收子进程时，
> 才会改用**重建**（这是重启改不了的属性）。

> 关于端口检查：跟随和导航**共用主机的网络端口**。如果导航正在运行，这些端口被它占着
> 是正常的，脚本能区分"我们自己的残留"和"别人的"，**只会对前者报警**。所以看到
> "被本栈以外的进程占用"这行不是错误，不用处理。

**成功标志**：

```
== follow stack shutdown ==
[ OK ] swept N process(es) from the container PID namespace (container keep-alive pid N preserved)
[ OK ] ports released: 50051 50061 50071 50081 50091 50093 7447
[ OK ] can_ranger 接口保留（底盘控制权已由 rbnx shutdown 释放）
[ OK ] follow stack shutdown complete — ports released
重启容器（给下一轮一个干净的进程表）…
[ OK ] 容器已重启：running，Init=true，僵尸 0
```

**确认关干净**：`bash scripts/follow.sh status` → 两个底盘进程都应为 0。

**恢复导航**：

```bash
cd /mnt/ssd/wxf/jiaofu/robot-agilex-ranger_mini_v3
bash start-no-arm.sh
```

### 4.8 首次/换环境准备 —— `run_container.sh`

仅在**第一次使用**或**更换硬件配置**时需要：

```bash
bash scripts/run_container.sh follow
```

> ⚠️ 此命令会**重建容器**，会中断正在运行的跟随。

## 五、与车交互（语音调距）

这是跟随过程中**唯一可用的交互方式**：通过说一句话，改变车与你保持的距离。

### 5.1 支持的口令

| 你说 | 车的反应 |
|---|---|
| **靠近一点** | 目标距离 **减少 1 米**，车主动向你靠近 |
| **离我远一点** | 目标距离 **增加 1 米**，车停下等你拉开距离 |
| **保持 3 米** | 目标距离**直接设为 3 米** |
| 跟随距离设为 2 米 | 同上，设为 2 米 |
| 跟我保持 5 米距离 | 同上，设为 5 米 |

数字支持阿拉伯数字和中文数字，例如"保持**三**米""设置为**一点五**米"。

### 5.2 如何操作

1. 让机器人旁边的人对着**客户端设备**（手机/网页客户端）说话
2. 或者直接在客户端的**文字输入框**打字发送
3. 车会立即响应，不需要重起

### 5.3 使用前提

| 前提 | 检查方法 |
|---|---|
| 客户端已连接机器人 | 客户端界面上显示已连接 |
| 语音识别密钥已配置 | 检查 `.env` 里腾讯云密钥非空 |
| 意图路由服务在线 | `curl -s --noproxy '*' http://127.0.0.1:18080/v1/models` 有返回 |

### 5.4 说不通的情况

**口令必须与上表完全一致。** 多一个字都不认：

| 说法 | 结果 |
|---|---|
| 靠近一点 | ✅ 认 |
| **能不能**靠近一点 | ❌ 不认 |
| 跟紧一点 | ❌ 不认 |
| 别跟丢了 | ❌ 不认 |

> 听不懂时车**不会有任何反应**，也不会报错。**请照上表的说法说。**

### 5.5 改默认距离（不用语音）

改配置文件，**需要重起**：

```bash
nano robonix_manifest.yaml
```

找到 `target_distance_m`（约第 188 行），改成 0.5 ~ 7.0 之间的值，然后：

```bash
bash scripts/follow.sh stop
bash scripts/follow.sh start
```

## 六、跟随行为说明

### 6.1 正常表现

| 人的动作 | 车的反应 |
|---|---|
| 往后退 | 加速追上来（越远越快，最快 0.25 米/秒） |
| 缓慢靠近 | 减速，到设定距离停下 |
| 继续靠近 | **停住不动**（本功能禁止倒车） |
| 左右移动 | 转向跟住，同时保持距离 |
| 走出画面 | 停止前进 |

### 6.2 以下现象是设计如此，不是故障

| 现象 | 原因 |
|---|---|
| 人比设定距离近时车不动 | 车想退但被禁止倒车，只能停住 |
| 人不在画面里车也在动 | 本功能没有"无人自动停"的判断 |
| 车冲着障碍物去 | 本功能没有避障 |

### 6.3 速度上限

| 项目 | 数值 | 限制来源 |
|---|---|---|
| 前进最快 | **0.25 米/秒** | 底盘守护层 |
| 转向最快 | **0.30 弧度/秒** | 上游速度平滑器 |
| 最小转弯半径 | **0.81 米** | 底盘守护层 |

> 速度链上有多层限制，**实际生效的是最严的那一层**：前进被守护层压到 0.25，转向被平滑器压到 0.30。另外急弯时转向还会被进一步压低以满足最小转弯半径。

> 转弯半径限制的作用：底盘在急弯时会**丢掉前进、只原地打转**，限制转向速度可以保住前进，让车持续跟上来。

## 七、安全停止

### 7.1 跟随中让车停下

| 方法 | 操作 | 适用 |
|---|---|---|
| **遥控器**（最快） | 按遥控器停止/急停键 | **推荐，任何时候都有效** |
| 人走出画面 | 被跟随的人离开摄像头视野 | 车会自动停止前进 |

> ⚠️ **目前没有"暂停跟随但不关服务"的软件命令**。要立刻停车，**用遥控器**。

### 7.2 完全停止跟随

见第 4.7 节「关栈」。

## 八、故障速查

| 现象 | 处理 |
|---|---|
| **车完全不动** | 跑 `check`，看哪一项未通过 |
| **起栈被拒绝** | 按提示处理：跟随残留 → `stop`；导航栈在跑 → 先停导航 |
| **OK 条数不是 16** | 看启动日志里的 `FAIL` 行 |
| **车只转圈不前进** | 人比设定距离近，请退到设定距离以外 |
| **车不停** | **按遥控器急停**，然后 `follow.sh stop` |
| **说话车没反应** | 口令是否与 5.1 表完全一致；客户端是否已连接 |
| **雷达 FAILED** | 主机雷达网口地址不对，需在导航仓执行 `setup-hw.sh` |
| **命令报 sudo 错** | 回仓库目录执行 `sudo -v` 输密码 |
| **端口被占起不来** | 脚本会指出占用端口；跟随残留 → `stop` 后重试 |
